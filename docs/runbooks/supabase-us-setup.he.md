# הקמת Supabase לפרויקט האמריקאי (ailab-us): מדריך למאיר, לחיצה אחרי לחיצה

> כמה זמן: בערך 20 דקות, מתוכן 10 דקות של המתנה.
> מה צריך לפני שמתחילים: תיבת המייל של הדומיין החדש (לא meir@ai-lab.co.il ולא laviemb@gmail.com). כך החשבון שייך מההתחלה למותג החדש, ולא נצטרך להעביר אותו אחר כך.
> עלות: 0. הפרויקט נפתח בתוכנית Free. אם החשבון מחובר לתוכנית בתשלום, הסקריפט עוצר ולא יוצר כלום.

## שלב 1: פותחים חשבון Supabase עם המייל החדש
1. פותחים בדפדפן חלון גלישה בסתר (Cmd+Shift+N), כדי שלא תיכנס אוטומטית לחשבון הישן.
2. נכנסים ל-https://supabase.com/dashboard/sign-up
3. ממלאים **Email** (המייל של הדומיין החדש) ו-**Password**, ולוחצים **Sign Up**. לא לוחצים על "Continue with GitHub".
4. פותחים את תיבת המייל החדשה, ולוחצים על הקישור במייל **Confirm your signup**.
5. בחזרה ב-Supabase הוא מבקש ליצור ארגון (Organization):
   - Name: `AI Lab Pro US`
   - Type: `Personal`
   - Plan: **Free - $0/month**
   - לוחצים **Create organization**.
6. אם הוא מציע מיד ליצור פרויקט (Create a new project), **לא ליצור**. סוגרים את החלון או לוחצים על הלוגו למעלה. את הפרויקט הסקריפט יוצר.

הצלחה = רואים דף ריק עם הכיתוב "AI Lab Pro US" ובלי פרויקטים.

## שלב 2: יוצרים טוקן גישה (Access Token)
1. נכנסים ל-https://supabase.com/dashboard/account/tokens
2. לוחצים **Generate new token**.
3. Name: `ailab-us-setup`. אם יש שדה תוקף (Expires), בוחרים **30 days**.
4. לוחצים **Generate token**.
5. מופיע טוקן שמתחיל ב-`sbp_`. לוחצים על כפתור ההעתקה שלידו. **הוא מוצג פעם אחת בלבד.** לא שולחים אותו בצ'אט, במייל או בוואטסאפ.

## שלב 3: מדביקים את הטוקן בקובץ הסודות
1. פותחים **Terminal** (Cmd+רווח, כותבים Terminal, Enter).
2. מעתיקים ומדביקים את השורה הזו ולוחצים Enter:
   ```
   open -e ~/Desktop/ailab-pro-us/.secrets.env
   ```
3. נפתח קובץ ב-TextEdit. מוצאים את השורה `SUPABASE_ACCESS_TOKEN=`.
4. לוחצים מיד אחרי סימן ה-`=` ומדביקים (Cmd+V). בלי רווח ובלי מירכאות. אמור להיראות כך: `SUPABASE_ACCESS_TOKEN=sbp_...`
5. שומרים (Cmd+S) וסוגרים את TextEdit.

## שלב 4: מריצים את הסקריפט
באותו Terminal, מעתיקים ומדביקים כל שורה בנפרד ולוחצים Enter אחרי כל אחת:

1. עוברים לתיקייה:
   ```
   cd ~/Desktop/ailab-pro-us
   ```
2. בדיקה שלא משנה כלום (רק קוראת את החשבון):
   ```
   python3 tools/us_setup.py --plan
   ```
   הצלחה = שורה שמתחילה ב-`✅ יש מקום פנוי בארגון AI Lab Pro US`.
   אם כתוב "יש יותר מארגון אחד", הסקריפט מדפיס שורה כמו `--org abcd...`. מוסיפים אותה לסוף הפקודות הבאות.
3. ההקמה עצמה (לוקחת 3 עד 10 דקות, רוב הזמן הוא המתנה לשרת):
   ```
   python3 tools/us_setup.py --create
   ```
   אל תסגור את החלון עד שמופיעה השורה האחרונה.

## שלב 5: איך יודעים שהצלחנו
השורות האלה צריכות להופיע, בסדר הזה:
- `✅ ailab-us נוצר (..., us-east-1)`
- `✅ המיגרציות רצו`
- `✅ בדיקת RLS עברה (159 בדיקות ...)`. זו הבדיקה שלקוח אחד לא יכול לראות נתונים של לקוח אחר.
- `✅ Auth הוגדר ...`
- `✅ נכתב site/assets/config.js ...`
- `✅ ping() ... מחזיר ok`
- ובסוף: `✅ הכל הסתיים בהצלחה.` ואחריה רשימה בשם **"מה נשאר לעשות ידנית"**.

שורות עם ⚠️ (למשל "אין RESEND_API_KEY") הן לא תקלה. הן אומרות שהשלב הזה ידולג עד שיהיה מפתח.

אחר כך כותבים לקלוד: **"us_setup הסתיים"**. קלוד יריץ את `python3 tools/us_setup_check.py`, שבודק את הפרויקט האמיתי: הרשאות, ping, משימות cron, ושמחיקת משתמש אוטומטית (אחרי 30 יום מביטול) באמת עובדת.

## אם משהו נכשל
| מה כתוב | מה עושים |
|---|---|
| `❌ חסר SUPABASE_ACCESS_TOKEN` | הטוקן לא נשמר. חוזרים לשלב 3 ובודקים שאין רווח אחרי ה-`=`. |
| `❌ הטוקן צריך להתחיל ב-sbp_` | הודבק מפתח אחר. יוצרים טוקן חדש בשלב 2. |
| `❌ אין מקום פנוי` | בחשבון כבר יש 2 פרויקטים פעילים, בכל הארגונים יחד (המגבלה של Free היא למשתמש, לא לארגון). הסקריפט מציג את שמותיהם, ולא מוחק ולא משהה כלום. כותבים לקלוד. |
| `❌ ... בתוכנית 'pro' (בתשלום)` | הארגון בתשלום. יוצרים ארגון Free חדש (שלב 1, סעיף 5) ומריצים עם `--org`. |
| `❌ הפרויקט לא עלה תוך 15 דקות` | מריצים שוב את אותה פקודה. הסקריפט ממשיך מאיפה שעצר ולא יוצר פרויקט שני. |
| כל ❌ אחר | מעתיקים לקלוד את השורה עם ה-❌ (אין בה סודות, הסקריפט מסתיר אותם). |

מותר להריץ את הסקריפט כמה פעמים שרוצים. הרצה חוזרת לא יוצרת פרויקט נוסף, ורק מריצה שוב את המיגרציות (שבנויות לזה).

## מפתחות שיגיעו אחר כך
כשיש מפתח חדש, מדביקים אותו בקובץ הסודות (שלב 3, באותה שורה עם השם שלו) ומריצים רק את השלבים הרלוונטיים:
| מפתח | שורה בקובץ | פקודה |
|---|---|---|
| Resend (מיילים) | `RESEND_API_KEY=` | `python3 tools/us_setup.py --only auth,vault,secrets` |
| Claude API | `ANTHROPIC_API_KEY=` | `python3 tools/us_setup.py --only vault,secrets` |
| Google (כניסה עם Google) | `GOOGLE_OAUTH_CLIENT_ID=` + `GOOGLE_OAUTH_CLIENT_SECRET=` | `python3 tools/us_setup.py --only google,config` |

ב-Google Cloud צריך להוסיף ל-OAuth client את ה-Authorized redirect URI שהסקריפט מדפיס (`https://<ref>.supabase.co/auth/v1/callback`).
**מאיזה כתובת יוצאים מיילי הכניסה:** עד שהדומיין החדש מאומת ב-Resend, המיילים יוצאים מהכתובת ב-ai-lab.co.il שכבר מאומתת (השדה `senders.fallback` ב-`config/brand.json`). לכן מפתח ה-Resend צריך להיות מהחשבון שבו ai-lab.co.il מאומת.
**מתי מחליפים:** כשב-resend.com → **Domains** הדומיין החדש מסומן **Verified**, אומרים לקלוד "הדומיין מאומת ב-Resend". הוא ימלא את `smtp_from` ב-`config/brand.json` (למשל `hello@` בדומיין החדש) ויריץ `python3 tools/us_setup.py --only auth`. הצלחה = מייל קוד כניסה חדש מגיע מהכתובת בדומיין החדש.

## פרויקט Free נרדם אחרי 7 ימים בלי פעילות
- ב-Free, פרויקט בלי בקשות 7 ימים עובר להשהיה, והאתר מפסיק לעבוד עד שלוחצים Restore.
- הפתרון (כמו בפורטל העברי): GitHub Action יומי שקורא ל-`ping()`. הקובץ כבר קיים: `.github/workflows/supabase-keepalive.yml`. עד שמגדירים לו סודות, הוא מדלג בשקט ולא נכשל.
- להפעלה, אחרי ההקמה: ב-GitHub של הריפו → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**, פעמיים:
  - Name `US_SUPABASE_URL`, Secret: הכתובת `https://<ref>.supabase.co` (הסקריפט מדפיס אותה)
  - Name `US_SUPABASE_KEY`, Secret: המפתח הציבורי מ-`site/assets/config.js` (השורה `SUPABASE_ANON_KEY`)
  (או פשוט לבקש מקלוד להריץ `gh secret set`.)
- **שים לב:** GitHub מכבה לבד workflows מתוזמנים בריפו ציבורי שלא היה בו שום commit במשך 60 יום, ושולח על כך מייל ("scheduled workflows disabled"). כשמגיע מייל כזה: ב-GitHub של הריפו → **Actions** → בצד שמאל **supabase-keepalive** → כפתור **Enable workflow**. הצלחה = אחרי **Run workflow** מופיע וי ירוק.
- אם בכל זאת נרדם: supabase.com/dashboard → ailab-us → **Restore project**, מחכים 2–3 דקות.

## אחרי שהכל עובד
- הטוקן מהשלב 2 נותן שליטה מלאה בחשבון. כשקלוד מאשר שהבדיקות עברו, אפשר למחוק אותו ב-https://supabase.com/dashboard/account/tokens (Revoke) ולמחוק את הערך מהקובץ. כשיהיה צורך, יוצרים טוקן חדש.
- סיסמת מסד הנתונים נוצרה אוטומטית ונשמרה בקובץ הסודות בשורה `SUPABASE_DB_PASSWORD`. לא צריך לזכור אותה, ולא משנים אותה.
